## 1. 先定核心主张

- **一句话说清研究问题或核心结论**：在第 2–3 页之前必须让听众听到，不能埋在背景铺垫里。
- **一次汇报只论证一个主张**：不要试图讲完整篇论文。在限时内能被有力证明的那个论点才主线，其余材料移入附录。
- 开工前先写清三行：
  - 研究问题 / 待回答的疑问是什么
  - 核心主张 / 一句话贡献是什么
  - 支撑该主张的最关键证据是哪 2–3 条
- 若素材不足以支撑任何一句明确主张，先补研究或数据，不要用平铺的章节罗列代替论证。

## 2. 选择叙事脊柱

全篇只选一条脊柱并贯穿始终，不要在不同章节混用逻辑。

| 脊柱 | 结构 | 适用场景 |
| --- | --- | --- |
| **SCR（情境—冲突—解决）** | 已知/已确立 → 缺什么、哪里有争议或未解释 → 本工作的贡献 | 答辩、期刊会议口头报告；默认首选 |
| **漏斗（背景→缺口→方法→发现→意义）** | 宽背景收窄到具体问题，再给出方法、关键发现与引申 | 开题、综述型、组会汇报 |
| **结论先行** | 先抛结论，再逐条给支撑证据 | 限时短讲、基金评审、顾问委员会等耐心有限的资深听众 |

- 学术工作默认走 **SCR 或漏斗**；面向非专业听众的科普/路演才以视觉叙事优先（见 [scenarios.md](scenarios.md) 的模式选择）。
- 研究问题必须**独立成页**，不要嵌在动机页里；给听众一个锚点来评估后续全部内容。

## 3. 主张—证据映射

- 列出主线主张清单，逐条标注由哪一页、哪张图表/哪组数据支撑；反向检查每条证据服务于哪条主张。
- **互测**：
  - 盖住证据只读标题——标题若仍然成立，说明这页证据多余。
  - 盖住标题只看证据——结论若不明显，说明标注不足或标题不够准。
- 不支撑主线主张的材料：移入附录，或在组会等轻量场景中明确标为"补充/进行中"。
- 主张强度与证据等级匹配：有对照实验才说"优于"，只有趋势观察就说"提示/初步显示"，避免过度断言。

## 4. Action Title（结论式标题）

最重要的格式规则。每张内容页标题必须是一句**完整陈述结论（so-what）**，而不是名词标签。

| 不要用（话题标签） | 改用（结论式标题） |
| --- | --- |
| 实验结果 | 三个数据集上本方法指标均优于强基线 3.2–5.1 个点 |
| 相关工作 | 已有方法尚未解决多视角下的遮挡重建问题 |
| 数据 | 数据集覆盖 40 个受试者、三类动作与两种光照条件 |
| 方法 | 利用隐空间一致性约束消除跨帧闪烁 |
| 讨论 | 控制身份与姿态变量后提升依然稳定 |

规则：
- 标题一到两行；需要更长说明观点还不够锐利，先重想主张。
- 标题直接落在结论句；页面正文与图表只解释、不重复标题。
- 同类页面标题位置、字号、对齐保持一致。

## 5. 两个结构测试

大纲完成后、动手排版前，必须通过：

### Ghost Deck Test（幽灵稿测试）
只读各页标题，按顺序连读。它们应当能讲出完整论证；读不出完整故事，说明大纲逻辑有缺口——先改标题或重组结构，再做页面。

### Flow Test（衔接测试）
每一页都应是上一页的自然推论。若某一页拿掉后放到任何位置都不影响理解，它要么放错位置，要么本就多余。

### 单页职责测试
每页在论证中只承担一个明确角色（背景/缺口/问题/方法/证据/讨论/结论）。一页做两件事，就拆成两页。
